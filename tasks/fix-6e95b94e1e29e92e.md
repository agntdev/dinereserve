# fix-6e95b94e1e29e92e — Deterministic ref-code generation with no collision handling in the bot flow

**Weight:** 0.0000 (share of project budget)
**Reward:** 0 DRSV

`generateRefCode` (`booking.ts:26–41`) produces a 6-char ref code deterministically from `SHA-256(isoDate:slot:userId)` — the same user booking the same date+slot twice always gets the same code. The DB repository (`db/repository.ts:328–385`) has 8-attempt collision-retry when generating random codes, but the bot bypasses the repository and uses `saveBooking` (`booking.ts:58–88`) directly with `INSERT`. If a ref-code collision occurs (e.g., after rescheduling away and back to the same slot), `saveBooking` throws a unique-constraint violation, which `persistBooking` silently catches and logs (`bot.ts:309–311`). The user still receives "Booking confirmed!" with no indication the booking was rejected by the database.
