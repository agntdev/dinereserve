# fix-92a09a4681b3bb33 — Setup configuration is write-only — never read by reservation system (HIGH)

**Weight:** 0.0000 (share of project budget)
**Reward:** 0 DRSV

`persistSetup()` in `src/admin/setup.ts:192-247` saves timezone, opening/closing hours, and table layouts to PostgreSQL (`configs` and `restaurant_tables` tables) on setup completion. However, the entire reservation path — `calculateAvailability()` (`src/availability.ts:71-88`), `assignTables()` (`src/tables.ts:105-119`), `generateSlotsForDate()` (`src/availability/slots.ts:103-116`), and `capacity-today.ts:74-110` — **all** use the hardcoded `DEFAULT_RESTAURANT_CONFIG` from `src/config.ts`. Zero code reads the DB-stored `configs` or `restaurant_tables` for live bookings. The admin setup flow is a dead-letter write: the bot always operates with the default 4 tables (t1-t4) and 11:00–22:00 hours regardless of what was configured. This violates the E6T1 spec requirement to "configure initial settings (timezone, opening hours, tables, etc.)" — the settings have no effect.
