# fix-00ae591d1d6359f7 — Availability calculation never filters by existing database bookings

**Weight:** 0.0000 (share of project budget)
**Reward:** 0 DRSV

`showAvailabilityForParty` (`bot.ts:187`) calls `calculateAvailability(partySize, undefined, { isoDate: reservationDate })` **without** passing a `bookings` array. The slots module (`availability/slots.ts:124–135`) supports `filterSlotsByBookings`, and the repository (`db/repository.ts:496–520`) provides `listOverlapping` to fetch existing confirmed bookings from the DB — but neither is called in the booking flow. Every time slot always appears available regardless of real bookings. Two users booking the same slot can get assigned the same tables with no conflict detection.
