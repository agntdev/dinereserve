# fix-2f5a6b836d39c4c9 — Session pending reminder ignores configurable offset

**Weight:** 0.0000 (share of project budget)
**Reward:** 0 DRSV

`buildPendingReminder()` in `src/reminders.ts:52-61` defaults to `DEFAULT_REMINDER_OFFSET_MINUTES` (120). In `src/bot.ts:376`, `completeBooking()` calls it without passing the configured offset from the DB (computed by `getReminderOffsetMinutes()`). The `/reminders` handler then runs BOTH `deliverPendingSessionReminder` (session-based, offset=120) and `deliverDueRemindersForGuest` (DB-based, configurable offset) in sequence. If the admin changes the offset in the `configs` table, a guest calling `/reminders` may:
- Receive a session reminder at the wrong time (always 120min, ignoring the configured value)
- Receive **duplicate** reminders for the same booking in a single `/reminders` call (session reminder fires first; the DB path fires again because `reminder_sent_at` is still NULL at that point)

To fix: pass the configured offset to `buildPendingReminder()`, or sync the session pending reminder with the DB offset in `completeBooking()`.
