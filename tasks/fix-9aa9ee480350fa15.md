# fix-9aa9ee480350fa15 — Silent persistence failure on booking confirm, cancel, and reschedule

**Weight:** 0.0000 (share of project budget)
**Reward:** 0 DRSV

The `persistBooking` helper at `bot.ts:281–312` silently returns when `getBookingPool()` returns `null` (no `DATABASE_URL`). Its caller `completeBooking` (`bot.ts:349`) never checks the result — the user **always** sees "Booking confirmed!" regardless of whether data was persisted. The same pattern repeats for cancel (`bot.ts:577–585`) and reschedule (`bot.ts:339–342`): the callers ignore the boolean return of `cancelBookingByRefCode` / `rescheduleBookingByRefCode`. When the pool is missing, users get success messages for operations that never hit the database.

Additionally, `persistBooking` catches errors from `saveBooking` (`bot.ts:309–311`) with only `console.error`, so any write failure (e.g., unique-constraint violation on `ref_code`) is silently swallowed while the user still sees "Booking confirmed!"
